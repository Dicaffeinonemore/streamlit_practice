v1.53 — 노트북 성능 최적화 · 스테이지 4와 바르굴 전투 개선
작성일: 2026-10-29

목적
- Ryzen 230 / RAM 16GB / Radeon 760M 노트북 환경을 고려한 성능 개선.
- 스테이지 4와 바르굴 보스전에서 큰 이미지가 처음 표시될 때 생기는 멈춤을 우선 줄임.

1. 렌더링 해상도 조정
- 기본 내부 해상도를 960×540으로 제한. 고해상도 화면에서도 불필요한 픽셀 처리를 줄임.
- 설정에 화질 선택 추가: 기본 960×540 / 고화질 최대 1920×1080.
- 이펙트 감소(저사양)를 켜면 고화질 선택 상태에서도 기본 해상도로 제한.

2. 이미지 파일 분리와 스테이지별 로딩
- JS에 들어 있던 이미지 68개를 assets/runtime/ 파일로 무손실 분리.
- 초기 JS 응답 본문 약 196.1MiB → 7.6MiB. 이미지 자체는 별도 파일로 내려받음.
- 파일명에 원본 바이트의 SHA-256 앞 24자리를 사용하고 로컬 서버에서 장기 캐시 적용.
- 배경·바닥은 필요할 때 로드하고, 보스 이미지 시트는 해당 스테이지 진입 시 디코딩.
- 그래픽 준비 중 안내를 표시하고 실제 게임 루프의 시간 진행을 멈춤.
- Streamlit 컴포넌트에도 분리한 이미지 파일을 포함하도록 제공 목록 수정.
- 단일 HTML 내보내기는 이미지 데이터를 다시 포함하는 기존 방식 유지.

3. 스테이지 4와 바르굴 렌더링 개선
- 거대한 이미지 시트를 처음 그릴 때의 디코딩·래스터 준비 비용을 로딩 단계로 이동.
- 현재 스테이지와 공통 병사 시트의 CPU 래스터를 준비하고 작은 프레임 캐시를 재사용.
- 이전 스테이지의 CPU 래스터는 해제.
- 배경·바닥 축소 결과를 재사용하고, 바르굴 이펙트의 축소 프레임도 캐시.
- 캐시 개수 제한: 배경·바닥 이미지 8개, 축소 타일 8개, 프레임 96개, 이펙트 48개.
  각 캔버스 캐시의 메모리 상한은 24MiB. 큰 원본 시트·CPU 래스터 메모리는 별도.
- 바르굴 근접 공격의 타임라인 검색 결과를 WeakMap으로 재사용.

4. 성능 표시와 대기 화면 처리
- 설정에 성능 표시(FPS) 추가: FPS, 프레임 간격 p95, 연산·그리기 시간, 내부 해상도 표시.
- 측정 기록은 최근 180개로 제한. 콘솔의 BMK_PERF.snapshot()으로 캐시 상태 확인 가능.
- 일시정지·설정 등 정지 화면은 변경 시에만 다시 그림.
- 키·포인터·설정 변경·탭 복귀 시 대기 타이머를 취소하고 즉시 프레임 요청.

측정 결과 (변경 전 → 변경 후 독립 실행)
- 초기 생성 Image의 RGBA 환산 합계: 829.6MiB → 380.7MiB.
  이미지 너비×높이×4의 합계이며, 브라우저 전체 메모리 사용량은 아님.
- 스테이지 4 그리기 평균 / 최대: 5.38 / 544.4ms → 2.40 / 67.5ms.
- 바르굴 1페이즈 그리기 평균 / 최대: 4.32 / 486.5ms → 1.44 / 34.8ms.
- 바르굴 2페이즈 그리기 평균 / 최대: 1.55 / 90.1ms → 1.16 / 4.3ms.
- 개선 후 스테이지 4 최초 그래픽 준비 약 1.8초. 전투 중 첫 이미지 처리 비용을 앞당겨 수행.

측정 조건과 한계
- 분리된 임시 Chrome 프로필에서 스테이지 4 병사 4명과 바르굴 1·2페이즈의 십자 빙결 반복을
  각각 150번 업데이트·렌더링. 개선 후에는 그래픽 준비를 기다린 뒤 측정하고 준비 시간은 별도 기록.
- 장시간 실전 전투 전체의 성능 보증이 아닌 짧은 단일 실행 비교이며 최대 시간은 실행마다 달라짐.
- 최종 headless 환경은 그리기 없는 rAF 대조군도 평균 33.34ms, 전투도 약 30FPS였음.
  추가 진단에서 절전 상태에 따른 브라우저 갱신 제한을 확인함. 아래 추가 진단 참고.

추가 진단 — 로컬 실행의 30FPS 고정
- Windows 전원 상태 확인: 배터리 16%, 충전기 미연결, 시스템 절전 활성.
- 게임 스크립트가 없는 빈 페이지도 약 33.3ms 간격으로 갱신됨.
- 별도 임시 Chrome 프로필에서 에너지 절약만 끄자 게임 로드 후 무부하 갱신 간격
  33.34ms → 16.67ms로 바뀜. 사용자 브라우저·Windows 설정은 변경하지 않음.
- 실제 루프 약 2.2초 측정: 스테이지 4 일반 전투 56FPS(p95 17.3ms),
  바르굴 2페이즈 십자 빙결 반복 56FPS(p95 17.6ms). 최초 그리기 비용 포함, 장시간 보증 아님.
- 게임 코드의 30FPS 제한이 아닌 브라우저 절전 상태의 영향으로 확인.
  로컬 플레이 시 충전 연결 상태와 Chrome 설정 → 성능 → 에너지 절약 확인.
- 진단 도구: node tools/fps-diagnose.cjs / 원자료: artifacts/fps-variants.json.

전투 동작
- 이번 최적화에서 공격 타이밍·판정 범위·피해량·전투 좌표는 변경하지 않음.
- 기존 작업에 포함된 대시 찌르기와 필살기 수치에 맞춰 오래된 회귀 테스트 기대값을 갱신.

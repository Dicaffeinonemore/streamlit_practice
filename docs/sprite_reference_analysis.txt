원본 스프라이트 분석 및 구현 범위 (2026-10-15)

결론
첨부 5장은 배경·설명·번호·캐릭터·효과가 합쳐진 RGB 디자인 시트이다.
‘16프레임’이라는 글자가 독립된 16장의 이미지가 존재함을 뜻하지 않는다.
현재 작업은 원본 보존, 추출 후보, 애니메이션/스킬 데이터, 검수 화면,
검증된 자료만 허용하는 재생·전투 모듈까지이며, 7종의 실전 적용 완료가 아니다.
기존 게임의 legion_sprites.js / hd_sprites.js는 이 새 자료로 교체하지 않았다.
기존 게임의 보스 기술과 새 JSON의 원본 기술이 일치한다고 간주해서는 안 된다.

일반 병사
                대기   이동   공격      피격   사망
보병            6      8      6         4      4 (표기 5)
창병            6      8      6         4      4 (표기 5)
궁병            6      8      5+화살     4      4 (표기 5)
각 숫자는 식별된 인물 자세 수이며 완성된 독립 애니메이션 수가 아니다.
궁병 마지막 화살 구간은 별도 참고 패널로 저장했다. 인물 6번째 자세로 복제하지 않는다.
창끝·검기·망토가 인접 자세에 닿거나 배경에 섞인 부분은 경계 검수가 필요하다.

기사
대기 6, 이동 8, 아래쪽 피격 4, 사망 5개 자세를 분리 후보로 저장했다.
대기 번호는 공간 순서로 1,2,4,3,5,6이다. 번호대로 재정렬하지 않았다.
기본 공격은 6개 자세가 보이나 검기가 이웃 자세와 연결되어 개별 분리를 보류했다.
강공격은 6 표기와 달리 4개 인물 자세가 보인다. 2개를 생성하지 않았다.
오른쪽 중단 ‘피격 모션 (4프레임)’에는 5개 인물과 공격 검기가 함께 있다.
이 패널을 아래쪽 피격 모션과 합치지 않았다.

황금왕 아우렐리온
대기는 약 13개 자세로 보이며 표기 숫자는 16까지 있다. 이동은 16개로 보이나
밀집된 검/망토의 경계가 불명확하다. 등장 번호는 중복·역순이고 장면이 이어져 있다.
공격: 기본 베기, 올려치기, 내려찍기, 돌진 베기.
스킬: 3단 검기 선풍 / 황금의 엄벌 / 황금중파참.
사망 행은 있으나 별도 피격 행은 없다. 보스 전체 행은 원본 패널로 보존했다.
황금중파참은 행 높이가 작고 효과/번호가 불명확해 공격 범위와 타격 시점을
정확히 정할 수 없다. 이름만 보고 기존 다른 공격에 연결하지 않았다.

프로즌 그레이브로드
대기 8, 이동 9개 인물 자세가 식별되지만 각각 16프레임 표기이다.
공격: 서리 베기, 냉기 돌진, 얼음 파동, 빙결 회전베기, 서리 창 투척, 망자 소환.
스킬: 삼중 빙환참 / 절대영도 / 빙옥의 감옥.
등장·사망 행은 있으나 별도 피격 행은 없다.
이펙트 견본: 서리 검기, 얼음 기둥, 빙결 폭발, 냉기 파동, 얼음 파편.
견본은 연속 애니메이션으로 취급하지 않는다. 공격 중 겹친 검기·얼음은 독립 분리 보류.

블랙 문 엠페러
대기 8, 이동 8개 인물 자세가 식별되지만 각각 16프레임 표기이다.
공격: 월식 베기, 흑월 올려치기, 암흑 강화, 월영 돌진.
원본 표기는 ‘암흑 강화’이며 ‘암흑 강하’로 바꾸지 않았다.
스킬: 흑월 연참 / 종언의 월식 / 허무의 처형식.
등장·사망 행은 있으나 별도 피격 행은 없다.
이펙트 견본: 월식 베기 이펙트, 암흑 폭발, 허무의 기둥, 월식 잔흔 (바닥), 어둠의 파편.
넓게 이어지는 암흑 기둥/월식은 배경·인접 장면과 합성되어 개별 분리 보류.

산출물
assets/reference/sources: 수정하지 않은 원본 5장과 SHA-256 기록.
assets/characters, assets/bosses: 원본 패널 60개, 인물 원본 조각 139개,
                              동일 RGB를 유지한 투명 PNG 후보 139개.
data/animations: 7종별 모션 이름, 원본 좌표, 표기 수와 후보 수, FPS, 반복,
                 공통 캔버스와 발 기준점, 미확정 사항, 적용 허용 여부.
data/skills: 원본 공격/스킬 이름과 활성 프레임·판정 영역·피해량·쿨타임 설정 자리.
             미확정 값은 null/빈 배열, 스킬은 enabled=false이다.
data/enemies: 캐릭터 정의와 데이터 연결, 크기/렌더링 설정, 적용 보류 사유.
assets/effects, data/effects: 별도 효과 견본 10개의 원본 조각/투명 후보와 한국어 이름.
                             한 장씩 그려진 견본이며 연속 프레임은 아니다.
sprite-lab.html: 캐릭터/모션 선택, 재생/정지/한 장씩 이동, FPS, 반전, 정수 확대,
                 원본/투명 PNG 비교, 배경 전환, 발 기준선, 원본 패널과 전체 분석 목록.
src/animation/player.js: 반복/단발 재생, 프레임 진입 이벤트, 사망 마지막 프레임 유지.
src/combat/reference-combat.js: 검증된 자료만 받는 전투 연결 모듈. 활성 프레임별 판정,
                               좌우 충돌 영역, 중복 타격 방지, 연속기, 쿨타임, 행동 제한,
                               피격 시 공격 취소, 사망 완료 처리.
이 전투 모듈은 기존 game.js의 적 AI에 아직 연결하지 않았다. 미검수 자료를 연결하면
원본에 없는 공격/움직임을 대체 구현하게 되므로 자동 적용하지 않는다.

알파 추출의 한계
검은색을 일괄 투명화하지 않는다. 배경 계열 색 중 가장자리와 연결된 영역만
투명화 후보로 처리하며, 안쪽의 검은 갑옷 픽셀은 유지한다.
원본 RGB는 양자화·보간·재채색·인페인팅하지 않는다. 정수 좌표 이동만 사용한다.
단, 경계에 붙은 어두운 갑옷과 배경, 내부 틈의 배경, 바닥 그림자, 번호와
무기의 겹침, 이미 합성된 발광의 알파는 이 방법으로 정확히 복원할 수 없다.
139개 모두 검수 후보이며, 완벽한 배경 제거가 끝난 게임용 스프라이트가 아니다.
일부 추출 후보는 이웃 망토·무기나 배경 잔여물을 포함할 수 있다.
발 기준점은 사람이 읽은 시트 좌표의 초안이다. 원화의 실제 루트 이동 데이터는 없다.
원본에 없는 중간 자세를 늘리지 않았으므로 재생 시 매끄러운 16프레임을 보장하지 않는다.
FPS 8/10은 검수 화면의 기본 재생 속도이며 원본에서 확인된 시간이 아니다.
Nearest Neighbor 확대는 흐림을 피하지만 원본에 없는 세부 묘사를 만들어 주지는 않는다.

다음 적용에 필요한 자료/선택
1. 정확한 원본 구현을 위해서는 누락된 개별 프레임, 의도한 프레임 순서,
   배경과 분리된 PNG 또는 레이어 원본, 특히 보스 피격 및 공격 이펙트가 필요하다.
2. 그런 원본이 없다면 누락/겹침 부분의 대체 제작은 사용자 확인 후에만 수행한다.
   대체 제작물은 원본 복원이 아닌 새 제작임을 별도로 기록해야 한다.
3. 검수 후 gameReady와 enabled를 활성화하고, 실제 타격 자세를 확인한 activeFrames,
   hitboxes, damage, cooldownMs를 입력한 다음 기존 적 상태/AI를 연결한다.
   gameReady=true 표시만으로 확인되지 않은 후보를 승인해서는 안 된다.

실행/검증
server.py를 실행한 뒤 게임 타이틀의 ‘원본 스프라이트 검수’를 누른다.
또는 실행된 서버 주소의 /sprite-lab.html을 연다. 포트는 8000~8029 중 선택된다.
Streamlit에서는 상단 ‘화면’ 선택에서 ‘원본 스프라이트 검수’를 고른다.
Streamlit용 검수 HTML에는 모든 JSON과 이미지가 내장되어 별도 파일 서버가 필요 없다.
tools/extract_reference_sprites.py --source-dir "원본 이미지 폴더" 로 재생성할 수 있다.
재생성은 검수용 JSON도 덮어쓰므로 수동 검수 수정 전 별도로 보관해야 한다.
Python 검증: python tests/reference-assets.py (Pillow 필요)
Node 검증: node tests/reference-runtime.cjs
브라우저 검증: node tests/sprite-lab.cjs (Chrome/Edge, Node, Python 필요)
기존 게임 회귀 검증: node tests/regression.cjs
자동 검사는 색상·좌표·상태/타격 코드의 무결성을 확인하며 원화 미술 검수를 대체하지 않는다.

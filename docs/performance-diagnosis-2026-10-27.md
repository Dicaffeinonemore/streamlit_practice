# 흑월의 기사 로컬 성능 진단 — 2026-10-27

사용자가 보고한 증상: 이동·일반 전투 내내 버벅임.
게임 동작 코드는 변경하지 않고 별도 Chrome 프로필로 비교 측정했다.

## 결론

GPU 가속을 사용하지 않는 환경에서 **고해상도 Canvas와 피격 brightness 필터**가 결합하면 심한 프레임 저하가 재현된다. 시작 시 모든 자산을 동시에 로드하는 구조도 큰 메모리 부담과 초기 멈춤을 만든다.

사용자가 실제 플레이한 브라우저의 가속 설정·창 크기·GPU 상태는 이번 측정으로 확인하지 않았다. 따라서 아래는 재현된 병목 조건이며, 사용자 세션의 원인이 확정된 것은 아니다. GPU 가속이 켜진 독립 브라우저에서는 지속적인 저하가 재현되지 않았다.

## 비교 측정

`node tools/perf-diagnose.cjs`와 `PERF_SOFTWARE=1 node tools/perf-diagnose.cjs`를 사용했다. PowerShell에서는 `$env:PERF_SOFTWARE='1'` 설정 후 실행한다. 스크립트는 별도 임시 프로필과 로컬 정적 서버를 사용하고 종료 시 자신이 실행한 브라우저와 서버를 닫는다.

1스테이지 일반 적 4명을 배치했다. 이동·공격 측정은 게임 루프를 실행하고, 양방향 이동과 J 공격을 입력하며 180개 프레임 간격을 수집했다. 고정 장면 비교는 게임 갱신을 멈추고 각 조건에서 100번 그렸다. 고정 피격 비교는 적 4명의 flash를 유지한 부하 비교이며 일반 전투 전체의 평균으로 해석하면 안 된다. 1배/3배는 같은 화면에서 내부 Canvas 해상도만 변경했다. 짧은 단일 실행 결과이므로 통계적 성능 보증이 아니다.

## 병목과 코드 근거

1. **고해상도 렌더링 비용** — `game.js:10`의 `fitCanvas()`는 CSS 너비×devicePixelRatio에 따라 배율을 최대 3으로 올린다. 기본 960×540이 최대 2880×1620이 되어 처리 픽셀 수가 9배가 된다. 소프트웨어 렌더링에서는 실제 이동·전투 성능에 큰 영향을 줬다.
2. **피격 필터 비용** — `named-runtime.js`의 `paintNamedFrame()`은 피격 시 `ctx.filter='brightness(2)'`를 설정한다. 플레이어와 보스 런타임에도 유사한 필터가 있다. 소프트웨어 3배 비교에서 번쩍임만 비활성화했을 때 render 평균이 77.74ms에서 7.44ms로 감소했다. 소프트웨어 처리 시 큰 비용이 발생한다는 것은 확인했지만, 브라우저 내부의 필터 중간 버퍼 크기까지 측정한 것은 아니다.
3. **자산 일괄 로딩과 메모리 부담** — `index.html:447` 이후 모든 스테이지·보스 아트 스크립트를 동기 로드한다. 실제 JS 응답 본문 합계는 204,857,387바이트(약 195.4MiB), 생성된 Image는 77개다. 이미지 naturalWidth×naturalHeight×4 합계는 824.1MiB이고, JS heap 측정값은 약 582MiB였다. RGBA 환산량은 실제 GPU 상주 메모리나 프로세스 실측 사용량이 아니며 heap과 단순 합산하면 안 된다. `named-art.js`의 atlas만 2048×9840, RGBA 환산 76.9MiB다. 첫 1스테이지 렌더 비교에서 단일 render 166.8ms, 프레임 간격 216.6ms가 관측됐다. 이미지 디코드·첫 사용·업로드 중 어떤 단계인지 분리하지는 않았다.
4. **버튼 DOM 갱신은 부차적** — `game.js:2860`의 `updateSkillButtons()`가 매 렌더마다 텍스트와 속성을 쓴다. GPU 가속 켬 고정 장면에서 갱신 제거로 render 평균은 약 0.95ms에서 0.67ms로 감소했지만, 이것만으로 지속적인 심한 버벅임을 설명하지 못한다.

전투 update 비용은 이동·전투 측정에서 평균 약 0.07~0.11ms였다. 이번 일반 적 4명 조건에서는 AI/충돌 계산이 주요 병목이 아니었다. 보스·다수 투사체·장시간 플레이는 별도 검증이 필요하다.

추가로 걷기는 10장/900ms(포즈 약 11.1회/초), 일반 공격 적중은 3/3/7틱의 hitstop이 설정되어 있다. 화면 FPS가 높아도 캐릭터 포즈의 끊김이나 적중 순간의 정지는 느껴질 수 있다. 이는 실제 프레임 저하와 구별해야 한다.

## 개선 우선순위

1. 사용자가 플레이한 브라우저의 GPU 가속 상태와 실제 `RENDER_K`를 확인한다. 현재 측정은 그 세션을 대체하지 않는다.
2. 내부 해상도를 960×540으로 고정하거나 품질 설정에서 배율을 제한한다. 도트 게임이므로 CSS 확대 방식도 비교할 수 있다.
3. 피격 효과는 매 프레임 filter 처리 대신 프레임별 캐시 또는 가벼운 오버레이 방식으로 바꿔 같은 조건에서 검증한다.
4. base64 이미지가 들어 있는 대형 JS를 이미지 파일로 분리하고, 현재 캐릭터·스테이지에 필요한 자산부터 로드한다. 파일 분리만으로 최종 이미지 메모리 사용량이 줄어드는 것은 아니며 지연 로딩·해제가 함께 필요하다.
5. 스킬 버튼은 표시값이 달라질 때만 갱신한다.

# 바렐 combo0 새 첨부본 검수 — 적용 완료

2026-10-25 후속 요청에 따라 경계를 다시 검수하고 **신규 10프레임을 실게임 기본값 `aseprite10`으로 적용했다.** 아래 보류 기록은 적용 전 이력이다.

F5~F8의 검·부츠 접점을 확대해 검 끝의 실제 윤곽을 확인하고, 원본 RGB를 유지하면서 투명 배경과 프레임 소유 영역을 정리했다. F1·F9를 포함한 인접 망토의 잔여 픽셀도 제거했다. 10개 프레임 모두 단일 연결 성분·캔버스 여백·원본 RGB·지면 정렬 검사를 통과했다.

로컬 Chrome과 실제 Streamlit iframe에서 10프레임 재생, 350ms, 피해량·이동량 유지, 히트스톱, 콤보 연결, 취소, 좌우 반전 및 실패 시 6프레임 폴백을 검증했다.

**현재 리소스, 코드 위치, 테스트 명령, 미검증 범위 및 복구 방법은 [최종 적용 보고서](barel-combo0-10-implementation.md)를 참고한다.**

## 게임 연결 및 테스트 상태

- 신규 게임용 10프레임 PNG·Aseprite JSON: **생성·연결 보류**. 진단용 JSON은 애니메이션 리소스가 아니다.
- 기존 연결: `barel-runtime.js`의 `barelPlayerFrame()` → `barelFrame('combo'+p.combo, ...)`, `paintBarel()` → `BAREL_ATLAS`.
- `legacy` / `aseprite10` 모드 설정과 자동 폴백의 실제 게임 연결: **보류**. 현재 `aseprite10`을 기본값으로 바꾸지 않았다.
- `game.js`, `motion.js`, `barel-art.js`, `barel-runtime.js`, `index.html`, `server.py`, `assets/barel/atlas.png`, `assets/barel/frames.json`의 작업 전후 SHA-256 일치 확인.
- Aseprite CLI로 진단 이미지 6개 생성. 원본 해당 영역과 픽셀 일치 검사.
- 새 10프레임의 브라우저/Streamlit 재생, 350ms 종료, 타격/피해량, 히트스톱, 콤보 연결, 피격·대시·취소, 크기·지면·전진·발 미끄러짐, 좌우 반전, 로딩 실패 폴백: **미검증**. 새 리소스가 게임에 연결되지 않았으므로 완료로 표시하지 않는다.

공격 시간 350ms, 타격 구간 `[128.5,230)ms`, 콤보 연결 267.5ms와 전투 로직은 수정하지 않았다. 최종 프레임 시간표 `[40,30,35,25,25,30,45,25,40,55]`는 리소스 확정 후 Aseprite JSON에 적용할 요구사항이며, 현재 새 첨부본에 연결된 메타데이터가 아니다.

## 재개에 필요한 파일과 복구

**배경 체크무늬가 없는 진짜 투명 배경의 10프레임 `.aseprite` 원본** 또는 **서로 겹치지 않는 F01~F10 투명 PNG**가 필요하다. 특히 F5~F8의 검과 뒤쪽 부츠 윤곽이 각 프레임에 완전히 남아 있어야 한다. 동일 크기 캔버스와 지면/몸통 기준점을 제공하면 원본 픽셀을 재해석하지 않고 렌더링 메타데이터로 정렬할 수 있다.

현재는 기존 6프레임이 계속 재생되므로 복구 명령이나 설정 변경이 필요 없다. 새 투명 리소스가 확정되면 그 리소스로 모드 선택·자동 폴백을 연결하고 실제 브라우저와 Streamlit에서 검증한다.
